PostgreSQLの保守担当への着任、おめでとうございます。

`psql`はPostgreSQLの標準コマンドラインインターフェース（CLI）です。ここでは、基本的な接続方法と、日常の保守業務で頻繁に使用するコマンドをまとめています。

---

## 1. psqlでの接続方法

基本的にはターミナル（またはコマンドプロンプト）から `psql` コマンドを実行します。

### 基本的な接続コマンド

```bash
psql -h <ホスト名またはIP> -p <ポート番号> -U <ユーザー名> -d <データベース名>

```

* **ローカル環境（デフォルト設定）で接続する場合:**
```bash
psql -U postgres -d mydb

```


* **リモートサーバーに接続する場合:**
```bash
psql -h 192.168.1.100 -p 5432 -U dbuser -d production_db

```


*実行後にパスワード入力が求められます。*

### よく使う接続オプション

* `-h` (`--host`): 接続先サーバーのホスト名またはIPアドレス（省略時はローカルホスト）
* `-p` (`--port`): ポート番号（デフォルト: `5432`）
* `-U` (`--username`): 接続するデータベースユーザー名
* `-d` (`--dbname`): 接続するデータベース名

## 2. インタラクティブメタコマンド（`\`から始まるコマンド）

`psql` に接続した状態で実行するコマンドです。すべて先頭にバックスラッシュ（`\`）を付けます。

### 接続・基本情報

| コマンド | 説明 |
| --- | --- |
| `\l` または `\list` | データベースの一覧を表示 |
| `\c <DB名>` | 指定したデータベースに接続を切り替える（reconnect） |
| `\conninfo` | 現在の接続情報（ユーザー、DB、ホスト、ポート等）を表示 |
| `\q` | psqlを終了する |

### オブジェクトの確認

| コマンド | 説明 |
| --- | --- |
| `\dt` | 現在のDB内のテーブル一覧を表示 |
| `\d <テーブル名>` | テーブルのカラム構造、型、インデックス、制約などの詳細を表示 |
| `\dn` | スキーマ一覧を表示 |
| `\du` | ユーザー（ロール）一覧と権限を表示 |
| `\di` | インデックス一覧を表示 |
| `\dv` | ビュー一覧を表示 |

### 表示・設定

| コマンド | 説明 |
| --- | --- |
| `\x` | 縦表示（拡張表示）モードのON/OFF切り替え（カラムが多いテーブルの見づらさを解消） |
| `\timing` | SQLの実行時間を表示するモードのON/OFF切り替え |
| `\e` | エディタを開いて直前のSQLを編集・実行する |
| `\?` | psqlメタコマンドのヘルプを表示 |
| `\h <SQL命令>` | 指定したSQL構文（`SELECT` や `ALTER TABLE` など）のヘルプを表示 |

## 3. 保守業務でよく使う管理用SQL句

保守作業では、システム状態の監視や調査のために以下のSQLコマンドやシステムビューを頻繁に利用します。

### 動作中クエリ・接続状態の確認

現在実行中のプロセスやロック状態を確認します。

```sql
-- 現在接続中のアクティブなクエリ一覧を表示
SELECT pid, usename, datname, client_addr, state, query 
FROM pg_stat_activity 
WHERE state != 'idle';

```

### 長時間実行されている処理の強制停止

応答がなくなったクエリやブロックされている処理を停止させます。

```sql
-- 指定したPIDのクエリを安全にキャンセル（接続は維持）
SELECT pg_cancel_backend(<pid>);

-- 指定したPIDのプロセス自体を強制終了
SELECT pg_terminate_backend(<pid>);

```

### テーブルサイズ・ディスク容量の確認

ストレージ容量の監視や大容量テーブルの特定に使用します。

```sql
-- テーブルサイズ（インデックス含む）を人間が読みやすい形式で表示
SELECT relname AS table_name,
       pg_size_pretty(pg_total_relation_size(relid)) AS total_size
FROM pg_catalog.pg_statio_user_tables
ORDER BY pg_total_relation_size(relid) DESC;

```

## 4. 保守担当者向けワンポイントアドバイス

1. **`pg_dump` / `pg_restore` の確認**
データベースのバックアップと復元には `psql` ではなく、コマンドラインツールの `pg_dump`（単一DBのバックアップ）や `pg_dumpall`（全DB・ロールのバックアップ）を使用します。
2. **本番環境での実行前確認**
更新・削除操作（`UPDATE`, `DELETE`）を行う際は、必ずトランザクションを開始して確認することをおすすめします。
```sql
BEGIN;
-- 処理の実行
DELETE FROM users WHERE last_login < '2020-01-01';
-- 影響件数を確認後、問題なければ COMMIT、やり直す場合は ROLLBACK
ROLLBACK;

```
