# 記事ネタ帳・公開ロードマップ

「明日使える生成AI」の記事ネタのストックと、公開順序を管理する文書。方針は[content-strategy.md](content-strategy.md)、文体は[writing-style.md](writing-style.md)を参照する。

- ネタが増減するたびに本書を更新する。方針レベルの変更（カテゴリ追加、ペルソナ変更など）はcontent-strategy.mdで行う
- 記事公開時は2章の「リンク待ちリスト」を確認して橋渡しリンクを追記し、[content-strategy.md](content-strategy.md)6章のトリガーを確認する

## 2. 公開順序の依存関係

### 強い依存（この順序を守る）

| 後続 | 先に公開しておく記事 | 理由 |
|---|---|---|
| 3. プロンプト設計の型（全5回） | 2. プロンプトの基礎体力（全2回） | 入門編のため |
| 5. ステップアップ編（全4回） | 3. プロンプト設計の型（全5回） | 応用編のため |
| 9. 自分のツール・エージェント（全2回） | 8. AIの拡張のしくみ（全4回） | 8がハンズオンの前提知識となるため |
| 8-② 公式Skillsを覗いてみよう | 8-① AIの「指示の与え方」を整理する | ①の書式と照らし合わせて読むため |
| 9-② エージェントを作ってみよう | 9-① 簡単なツールを作ってAIに使わせる | ①で作ったツールを使用するため |
| 10-① セキュリティ第2弾 | 1-① セキュリティ設定を見直そう | 第1弾が公開済みである必要があるため |
| 10-② AIを利用した設計の方法論 | 1-⑧ コンテキストが溢れるとどうなる？ | コンテキストウィンドウの限界を前提に進めるため |

### 弱い依存（リンク待ちリスト）

記事末尾の橋渡しリンク。**リンクを省いて公開し、リンク先の公開時に追記する**。追記後にチェックを入れる。

- [ ] 1-③ AIは「持っている知識」しか扱えない → 7-①（手軽な方法）／9-②（本格的な方法）※少なくとも7-①を先に公開しておく
- [ ] 1-② ハルシネーションとは何か → 1-③ AIは「持っている知識」しか扱えない（1-②は2026-08-31公開済み。予告のみでリンクなし。1-③公開時に追記）
- [ ] 1-① セキュリティ設定を見直そう → 10-① セキュリティ第2弾（1-①は2026-08-24公開済み。予告のみ。10-①公開時に追記）
- [ ] 1-⑧ コンテキストが溢れるとどうなる？ → 10-② AIを利用した設計の方法論
- [ ] 1-⑨ 現場でAIが使えないときに → 7-②（相互リンク）
- [ ] 6-⓪ 業務の棚卸し → 6-①〜⑤ 業務別活用事例
- [ ] 5-④ 自分だけのエージェントとして独り立ちさせる → 9-② 本格的なエージェント構築
- [ ] 6. テンプレート活用術（2本） → 3. プロンプト設計の型シリーズ（相互リンク）
- [ ] 8-① AIの「指示の与え方」を整理する → 冒頭の交通整理から 1-③ ／ 7-① ／ 9-②
- [ ] 7-② 「社外に出せない」現場のためのAI選び → 1-① セキュリティ設定を見直そう（1-①は2026-08-24公開済み。執筆時にリンク可能）
- [ ] 7-④ コードレビューに使えるのはどれ？ → 10-① セキュリティ第2弾

### 順序を組むときの原則

- 基礎シリーズ（1. 生成AIのきほん）を連続投稿にせず、業務Tips系と交互に挟む
- `開発者向け`（8〜11）はStep1・2の記事の間に挟み込み、連続させない
- `ニュース`（12）は週1ローテーション枠外で話題発生時に差し込む

## 4. シリーズ企画一覧

1. **生成AIのきほん**シリーズ（`生成AIのきほん`、Step1入口・全9回想定）
   1. AI利用で大事なこと①：セキュリティ設定を見直そう（※10-①へ橋渡し）
   2. AI利用で大事なこと②：ハルシネーションとは何か、なぜ起こるのか
   3. AIは「持っている知識」しか扱えない ― 社内情報・ドメイン知識という壁（※社内情報未所持がハルシネーションにつながる切り口で執筆。7-①と9-②へ橋渡し）
   4. AIに「このモデルの使い方」を聞いてみよう
   5. プランモードって何？「モード」の違いを理解する
   6. AIが扱えるファイル・形式を聞いてみよう（input / output）
   7. AIツールの便利機能、こんな時に使おう（※具体機能を「どう使うか」に特化。抽象的な使い道は6-⓪が担う）
   8. コンテキストが溢れるとどうなる？AIの「物忘れ」「混乱」現象
   9. **現場でAIが使えないときに、今やっておくこと** ― L0（全面禁止・未導入）向け。業務外での練習・導入準備を扱う。価値の軸は**②立ち位置**と**③選別と順序**
   - ※1・2は執筆時に統合か分離を判断
   - ※9と7-②の棲み分け: 7-②は「制約レベル別のツール選定」、9は「選べない読者の業務外の準備」

2. **プロンプトの基礎体力**シリーズ（`プロンプト設計`、全2回想定。型シリーズの前提）
   1. 文章を構造化して書く基本 ― 章立て、結論ファースト・PREP法
   2. プロンプトの書き方の基本（Markdown記法で構造化する）

3. **プロンプト設計の型**シリーズ（`プロンプト設計`、全5回想定）
   1. 要約 ― 青空文庫など**著作権切れの小説**を使った体験デモ
   2. 企画書化
   3. 添削
   4. 壁打ち
   5. 役割設定
   - 追加候補: 重み付けにより意外な出力を引き出す方法

4. **AIにキャラクターを与えてみよう**シリーズ（`プロンプト設計`、全2回想定）
   1. AIに性格を持たせる？ペルソナ設定でAIの個性・モノマネ力を引き出す
   2. 同じ文章を「映画のヴィラン風」「元気なギャル風」「かわいいキャラクター風」に言い換えてみる（デモ中心）

5. **プロンプト設計（ステップアップ編）**（`プロンプト設計`、全4回想定）
   1. AIにプロンプトそのものを書いてもらう方法
   2. 1回のプロンプト・チャットで終わらない作業をAIにやらせる方法
   3. 複数回のやり取りで生じた矛盾を、より上位のモデルにレビュー・修正してもらう方法
   4. 書いてもらったプロンプトを「自分だけのエージェント」として独り立ちさせる ― カスタムGPT／Claude Projects／Gemini Gemsなど（※9-②へ橋渡し）

6. **業務別活用事例**シリーズ（`業務効率化`、棚卸し1本＋全5回＋テンプレート活用術2回）
   - **⓪ 自分の業務を棚卸しして、AIに渡せる仕事を見つける**（`入口`タグ、標準型）― 下限読者向け。**業務棚卸し → 判定軸 → 実行**の構成。一次体験として**筆者の棚卸し実物リスト（失敗例含む）**を掲載
   1. 議事録
   2. メール
   3. 資料作成
   4. データ集計
   5. 企画立案
   - **テンプレート活用術**（2部構成。3シリーズと相互リンク）
     1. 業務別テンプレート集
     2. 「上手なテンプレートとは何か」を考える回 ― 仮説（**執筆時に検証・確定**）: 項目名を疑問文にする／不要項目の削除を明記／分量目安を指定／指示と成果物のテンプレートを分離

7. **ツール使い分け**シリーズ（`ツール比較`、全6回想定。比較型フォーマット。[content-strategy.md](content-strategy.md)5章準拠）
   1. ノートブック機能で「自分だけのナレッジ」を作る
   2. **「社外に出せない」現場のためのAI選び** ― 制約の型を軸にツールを当てはめる構成。1-⑨と棲み分け
   3. **長文要約はどれが強い？** ― 精度に加え、**入力上限**と**貼付かファイル添付か**の運用面を比較
   4. **コードレビューに使えるのはどれ？** ― 欠陥種別（null安全・境界値・性能・命名）を仕込み、指摘粒度や誤指摘の有無を検証。常駐先ソースが貼れない現場での使い道に着地
   5. **Excel・表データの処理はどれが得意？** ― **入出力の差**（ファイル直接処理・コード実行・xlsx返却）を検証。テキスト貼り付け手順も併記
   6. **無料プランだけでどこまで戦えるか** ― 無料枠で同日の業務を回し制限到達を検証。**変動が速い**ため検証時点を強調
   - ※ツール名は記載可、**常駐先での承認ツール名は非公開**（[writing-style.md](writing-style.md)4章）

8. **AIの拡張のしくみ**シリーズ（`開発者向け`、概念編・全4回想定）
   1. AIの「指示の与え方」を整理する ― Instructions / Skills / Agentsの概念、指定方法・呼び方の違い、書式（SKILL.mdなど）。**冒頭で「知識を足す」（1-③・7-①・9-②）と「機能・ツールを足す」（本シリーズ）を整理**
   2. Anthropic公式のSkills(https://github.com/anthropics/skills)を覗いてみよう
   3. MCP（Model Context Protocol）とは何か
   4. MCPを使うときの注意点 ― 有効化中のMCPサーバー・ツール一覧は常時トークンを消費するため、必要な時だけONにする運用

9. **自分のツール・エージェントを作ってみよう**シリーズ（`開発者向け`、ハンズオン編・全2回想定。8が前提）
   1. 簡単なツールを作ってAIに使わせる（例: 天気予報取得ツール）
   2. 簡単なエージェントを作ってみよう（①のツール＋AIで「今日のお出かけプラン」を提案）

10. **開発者としてのAI活用ノウハウ**シリーズ（`開発者向け`、実践編・全4回想定）
    1. セキュリティ第2弾：AIに与えてはいけない情報（認証情報・DB接続情報など）― 自動接続リスクを扱う。**一次体験**: 自社開発時にDB接続情報の管理問題へ直面した経緯
    2. AIを利用した設計の方法論 ― コンテキストウィンドウの限界を踏まえた仕様分解
    3. AIが得意な開発言語はどれ？ ― 型付き言語の有利さと実行環境整備の重要性
    4. 確率論と決定論の使い分け

11. **現場導入・推進**シリーズ（`開発者向け`、マネジメント編・全2回想定）
    1. 現場の生成AI導入レベルを診断してみよう
    2. 現場に生成AIを導入してもらうときのアピール方法

12. **ニュース**枠（随時執筆。[content-strategy.md](content-strategy.md)3章）
