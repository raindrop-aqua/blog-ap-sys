# 検証手順

記事 6-⓪「自分の業務を棚卸しして、AIに渡せる仕事を見つける」の検証データ。

狙い: 自分の業務リストから「AIにできそうなこと」を当てにいくのではなく、**AI自身に"抽象的にできること"を先に申告させ、そのリストを自分の業務に照らす**という逆順の手順を検証する。

条件: 各ツールとも**新規チャット**で投げる。同じ日にまとめて実施する。使ったモデル名を必ず記録する。

```
あなたができることを教えてください。

特に得意なものがあったらアピールしてくださいね。

回答にはみやすいように一覧もつけてください。
```

## 出力を見て気づいたこと

|---|---|---|
| ChatGPT | 分類表14行 ＋ グループ分けの一覧で約40語 | ①複雑なものを整理して構造を見つける ②ゼロ・曖昧な状態から一緒に形にする ③同じ内容を目的に合わせて別の形へ変換する |

| Gemini | 8項目 | 複雑な情報の構造化（整理・比較）／文脈に応じた柔軟な文章生成 |
| Copilot | 10項目 | 比較と構造化／文体のモノマネ／発想の拡張／推論と説明 |

### 1. 一覧はツールをまたいでほぼ一致した

4本すべてに共通して出た型:

- **比較**（全4本が「特に得意」と自己申告）
- **要約・抽出**
- **構造化・整理**（散らかった情報を表・箇条書きに）― 全4本が上位で強調
- **問題の分解**（大きい作業を小さいステップに）― ChatGPT / Claude / Copilot は「得意」
- **モノマネ・文体模写**（Copilot だけ「声・音声は不可、文章の"ノリ"のみ」と明記）
- 発想・ブレスト／推論／言語変換／創作／添削・校正

→ **どのツールで聞いても返ってくる地図はほぼ同じ**。読者は手元のツールでこの手順をそのまま使える。
　粒度と分類の切り方はツールで差が出た（ChatGPTは絵文字つき大分類、Geminiは8項目に圧縮）が、
　中身の型は変わらない。

### 2. 一覧に「出てこなかった」もの

4本とも自分を「答えを出す機械」ではなく **思考の相手・編集者・壁打ち役** として売り込んだ。
逆に一覧に出ないもの:

- 正確な最新情報を出す
- 大量データを正確に処理する
- 使う人の職場の事情・前提を踏まえる
- 最終判断をする（ChatGPT・Gemini は「最終判断は一緒に」と明記）

→ ここが「渡せると思ったのに外れた」が生まれる境界線。記事ではこの線を判定軸として使う。

### 3. 4本とも「壁打ち・一緒に考える」使い方を推してきた

ChatGPT「単に質問→回答と使うより『これ、どう考えればいい？』と投げると本領を発揮」、
Claude「一歩ずつ確認しながら進める」、Copilot「どれか一つ深掘りする？」と全ツールが対話へ誘導した。
受け身の利用より能動的な活用へ、という方向づけはツール側にも埋め込まれている。

### 4. この一覧は「実力の保証」ではなく「自己PR文」

なぜ4本とも似た口調で「思考の相手・編集者・壁打ち役」を売り込むのか。理由は積み重なっている。

- **システムプロンプト**: 各社ともモデルの手前に「有能で親身なアシスタントとして、分析や壁打ちを手伝い、
  次の一歩を提案する」旨の指示を入れている（Anthropic は Claude の分を公開）。隠れたバイアスというより製品の設計。
- **人間の好みでの強化（RLHF）**: 評価者はそっけない箇条書きより、benefit を語る答え・「〜しましょうか？」と
  次を促す型を高く評価する。自分について聞かれたときのこの口調はその積み重ね。
- **学習データ**: これらのツールを説明する文章（活用法記事・公式ドキュメント・"copilot" という名前自体）は
  圧倒的に「相棒・共同作業者」のフレーム。自己紹介を求めるとそのコーパスをなぞる。
- **モデルは自分の性能を内省できない**: 「何ができる？」への答えは、重みを調べた報告ではなく
  「有能なAIアシスタントならここで何と言うか」の生成。だから `★★★★★ 比較` はベンチマーク結果ではない。

→ 一覧は **試すべき「注文の仕方」のメニュー** として使う。実力は人間が自分の業務で試して判断するしかない。
　ステップ3で「得意」なはずの要約が筆者には微妙だった、というのがその実例。

→ 皮肉: 一覧に載らなかった「大量データを正確に処理する」は、開発者が最も酷使している用途
　（ソースコードの一括修正など）。**AIが自ら宣伝しない領域を、人間はいちばん重い作業で頼っている。**
　（この論点は開発者向けシリーズ 10-③「AIが得意な開発言語」あたりでも効く）

## ステップ2: 自分の業務に照らす

### 筆者が自由に書き出した業務（棚卸しの第一稿）

- 毎週の週報
- （個人的なもの）1日を振り返る日記 ※聞き手をギャルのペルソナにしている。話を広げてくれるので続く
- ホワイトペーパー等のPDFを読み込ませて要約・内容質問
- 正規表現を書いてもらう（開発）
- SQL・実行計画を分析してパフォーマンス悪化の原因特定（開発）
- ログ・スタックトレースを分析して原因特定（開発）

筆者の所感:「いざ挙げてみると、うまくAIを活用できていない気がする」

### 気づき: リストが一方向に寄っている

| 書き出したもの | 共通する性質 |
|---|---|
| 週報／日記／PDF要約QA／正規表現／SQL分析／ログ解析 | 全部ひとりでやる作業 ＋「答えをもらう」使い方（要約して・書いて・原因を教えて） |

一方、4ツールが「特に得意」と口をそろえたのは **比較・構造化・発想・壁打ち**（＝一緒に考える使い方）。
筆者のリストにはそれがゼロ。「活用できていない気がする」は錯覚ではなく、**使い方が一方向に寄っている**という診断になる。
→ 一覧に照らすと、自由な書き出しでは出てこない使い道が見える。これが手順の効き目。

### 「渡せると思ったのに外れた」仕事: PDFの要約・質問

- **要約**: 長文の文書だと、要約を読んでも全体が掴みきれない。素の「要約して」で投げている。
  仮説（未検証）: 出力形式を指定すれば理解しやすくなるかもしれない。
- **質問**: そもそも聞きたい質問が思いつかない。

→ 一覧の「構造化」「質問する・議論する」がちょうど空いている領域。
　次の検証で、素の投げ方と、形式指定＋AIに論点・質問を出させる投げ方を比べる（下記ステップ3）。

## ステップ3: PDF要約の投げ方を変えて比べる（Before / After）

素材: GLOCOM Discussion Paper 24-001（2024年4月）
　「画像生成AIについてのクリエイターの賛否は割れている」田中辰雄ほか、全21ページ
　https://www.glocom.ac.jp/wp-content/uploads/2024/04/GLOCOM_DISCUSSIONPAPER_No.24_2024-001-1.pdf
　- 一般公開されており読者も入手できる。常駐先の資料ではない
　- アンケート調査の報告で、図表・統計が多い。5章立て＋小節あり
　- ★注意: この論文はp2に著者自身の「要約」と「目次」を載せている。
　　→ 素の「要約して」だと、その要旨をなぞるだけの出力になりやすい（＝Beforeの狙いどおりの弱点が出る想定）
条件: 同じPDF・同じツール／モデル・新規チャット。

### Before（いつもの投げ方）

```
添付のPDFを要約してください。
```

### After（一覧の「構造化」「質問する」を使う）

```
添付のPDFについて、次の3つを出してください。
1. 章ごとに1行の要約（表形式）
2. この文書で筆者が最も伝えたい主張トップ3
3. この文書を実務で使うために、私が確認・検討すべき論点を5つ（質問の形で）
```

### 記録すること

- 実施日: 2026-09-09(水)
- ツール・モデル: ChatGPT（不明）／Claude sonnet 5／Gemini 3.6 Flash／Copilot（不明）
- 出力: `pdf-summary-{before,after}-{chatgpt,claude,gemini,copilot}.md`（8本）

#### 筆者の主観

- 「全体を掴む」目的では **Before のほうが分かりやすかった**。
  After は「章ごと表 ＋ 主張トップ3 ＋ 論点5つ」の3成果物を頭で組み直す必要があり、かえって重い。
  特に「論点を質問で5つ」は "掴む" 作業には効かない（別の目的＝質問出しには効く）。
  → **構造化すること自体は、掴みやすさに直結しない**。むしろ素の要約のほうが物語の流れで頭に入る。
- 未検証の別仮説: 掴みやすさの本当のレバーは **読者レベルの指定**（「小学生でもわかるように」）ではないか。
  年齢を下げるほど圧縮と平易化が強まる。→ ステップ4で検証。

#### 8本を読んだ分析（アシスタント）

**Before（素の「要約して」）**

- 4本とも p2 の要旨をなぞるだけでは終わらず、数字（利用27%／無断学習6割問題視／ハードライナー2〜3割）や
  下位の発見（コミケ参加者は熱心な利用者かつ批判者／プロアマ差なし／女性は否定寄り／出力枚数と評価の逆転）まで拾った。
  → 「要旨のコピペ」問題は出なかった。むしろ逆。
- 問題は別のところ。**全部が同じ重みで並ぶ「盛り合わせ」**になっている。
  特に ChatGPT の Before は8セクション＋表で長大。読み終えても「で、何が幹なのか」が残らない。
  Copilot は絵文字見出しで装飾過多、これも幹が見えにくい。
  → 筆者の「要約を読んでも全体が掴めない」は、要約が短すぎるからでも間違っているからでもなく、
  　**優先順位がついていない・形がない**から。長くすると余計に掴めなくなる。
- Before はどれも「この情報をどう使うか」が無い。純粋な内容の写し。

**After（章ごと表 ＋ 主張トップ3 ＋ 論点を質問で5つ）**

- **章ごと1行の表**: 4本とも5行のきれいな表。Before に無かった「持てる形」がこれで出た。
- **主張トップ3**: 4本が同じ3点に収束（①賛否は拮抗・多数派なし ②利用の半分は非公開のヒント用途 ③過渡期なので拙速な規制は避けよ）。
  ツールをまたいで一致 → この3点は信頼してよい、と読者に言える。
- **論点を質問で5つ**: ここが本命。「質問が思いつかない」に直接効く。しかも出てきた質問が非自明:
  - Claude: サンプルの代表性／「著作権を認める」は法解釈でなく世論である点／相関と因果の逆転／
    出力枚数と評価の矛盾をどう扱うか／2023年時点の調査で陳腐化していないか
    → **研究の読み方を疑う**方向の問い。
  - ChatGPT・Gemini: 用途区分／加工基準の社内ルール／学習データの受容性／レピュテーションリスク／暫定ルール＋定期見直し
    → **自社の方針に落とす**方向の問い。
  - Copilot: 論文のテーマを質問文に言い換えた程度で、新しい角度は弱め。
- ★発見: 「論点を出させる」と、ツールによって出る方向が違う（Claude＝方法論の吟味／ChatGPT・Gemini＝実務適用）。
  片方だけだと視野が狭くなる。**2ツールに投げて突き合わせる**と穴が減る。

**記事の骨として使える線**

1. 「要約して」がダメなのではなく、**素の要約は優先順位のない盛り合わせ**になる。長さは掴みやすさと無関係（ChatGPT Before が実例）。
2. 「章ごと1行の表」で形が出る。「主張トップ3」で幹が出る（4ツール一致で裏も取れる）。
3. 「私が確認すべき論点を質問で5つ」で "質問が思いつかない" が解ける。出た問いは自力では出しにくいもの。
4. メタで見ると、After で使ったのは**一覧に最初から載っていた「構造化」「判断支援」「質問する」**。
   新しいツールも新しい技も要らず、一覧のどれを"注文"するか変えただけ。これが「照らす」ステップの効き目そのもの。
