接続文字列のホスト名やDB名を、使うたびに書き換えるのが面倒でした。AIに一言頼んだら、入力欄の付いたチートシートがHTML1枚で返ってきました。このくらいの道具なら、頼めば作ってもらえます。その頼み方を、4つのAIで試し直した結果と一緒に置いておきます。

## 結論

頼んだのは3回です。聞く、残す、道具にする。

1. 知りたいことをAIに聞く
2. その答えを、あとで見返せるチートシートにまとめてもらう
3. チートシートの中で毎回書き換える部分を、入力欄にしてもらう

3回目で、自分専用の道具がHTML1枚でできます。サーバーもインストールも要りません。ブラウザで開くだけです。

2026年10月8日に、同じ3回を4つのAI（ChatGPT、Claude、Gemini、Microsoft Copilot）で試し直しました。4つとも道具を作ってくれました。ChatGPTだけは、「HTMLファイルで出力してください」ともう一言足すまで、ファイルにしてくれませんでした。

![Geminiが作った接続文字列の生成ツール。ホスト名・ポート・DB名などの入力欄と、ローカル開発・Docker・AWS RDSのプリセットボタン、生成されたpsqlコマンドや接続URIが並ぶ](/assets/img/posts/2026-10-12-ai-made-cheatsheet-tool-1.png)
_Geminiが作った道具。頼んでいないプリセットのボタンまで付いてきた。ただし、チートシートの中身は消えていて、psqlコマンドの末尾の `"?sslmode=prefer"` は無視されて効かない（補足を参照）_

ひとつだけ、期待と違ったことがあります。道具にしてと頼むと、4つとも元のチートシートの中身を捨てて、接続文字列を作るだけの道具にしてしまいました。「中身はそのまま残して」と言い足したら、4つとも残りました。

## 手順

筆者がこれをやったのは、2026年9月23日です。仕事でPostgreSQLを調べる必要があり、普段使っているVS CodeのGitHub Copilotに、psqlでの接続のしかたを聞きました。返ってきた答えを捨てるのはもったいなかったので、保守用のチートシートにまとめてもらいました。

ところが、チートシートの接続コマンドは、ホスト名やDB名が仮の値になっています。使うたびに自分の環境に書き換えるのが面倒でした。そこで、こう頼みました。

```
データベースへの接続文字列の中で可変になる部分をテキストボックスで編集できるようにしたいです。ツールとして使いたいのでHTML1枚で出力してください
```

やり取りはこの1回だけでした。入力欄にホスト名を入れると、チートシートの中のコマンドが書き換わります。自分の環境に合わせたコマンドが、その場でできあがります。

1回で済んだのは、完成形がだいたい頭の中にあったからだと思います。デザインの細部は別として、「どこを入力欄にして、何が書き換わればいいか」は決まっていました。

逆に、完成形が頭の中にないときは、自分が何を欲しいのか分かっていないことが多いです。そのときは、AIと話しながら、納得できる形まで作っていけばいいと思います。

試し直したときの1回目と2回目は、次の2つです。1回目の「保守を担当することになりました」は、試し直しのための前置きです。

```
今回、データベースの保守を担当することになりました。
PostgreSQLにpsqlで接続する方法と、よく使うコマンドを教えてください。
```

```
今の内容を、あとで見返せる保守用のチートシートとしてMarkdownで出力してください
```

PostgreSQLでなくても、同じ形で作れます。【コマンド名】や【作業名】を、自分が毎回書き換えているものに替えてください。

```
【コマンド名】の使い方と、よく使うオプションを教えてください。
```

```
今の内容を、あとで見返せるチートシートとしてMarkdownで出力してください
```

```
チートシートの内容はそのまま残して、【毎回書き換える部分】だけをテキストボックスで編集できるようにしてください。ツールとして使いたいのでHTML1枚で出力してください
```

入力する値は、試すだけなら `localhost` のような仮の値で足ります。業務のデータを使わないので、今は仕事でAIを使っていない方も、個人のチャットで同じことを試せます。

## 補足

作ってもらった道具は、すぐ使い始めずに、次の3つだけ見ています。

### 中身が消えていないか

試し直しでは、3回目の指示（上の当時のもの）を投げると、4つとも接続文字列を作るだけの道具になりました。2回目で作ったチートシートの、よく使うコマンドが1行も残っていません。

9月23日に作ったものは、コマンドが残っていました。違いは、当時はチートシートのファイルを渡していたかもしれない点です。そこで、チートシートのMarkdownを添付して同じ指示を投げ直しました。それでも、残ったのはChatGPTだけでした。当時なぜ残ったのかは、もう確かめられません。

再度実験を行い、同じチャットの続きで「チートシートの内容はそのまま残して」と言い足すと、4つとも残りました（チートシートのファイルを添付したあとのやり取りです）。上の3つ目のプロンプトに、この一言を入れてあるのはそのためです。

### パスワードがどう扱われるか

仕事で使う道具なので、ここは見ます。試し直しの4つでは、扱いが分かれました。

- ChatGPTとClaudeは、パスワードを既定でコマンドに含めませんでした。シェルの履歴に残るという注意書きも付いていました
- GeminiとCopilotは、入力したパスワードをそのままコマンドに埋め込みました。Copilotは、最初から `password` という値が入っていました

### 出てきたコマンドが動くか

出てきたコマンドのうち、見ていて怪しかった2つを、psql 17.5で叩いてみました。どちらも、psqlの仕様に合っていませんでした。

- ChatGPTの道具は、パスワードを含める設定にすると `--password='値'` という形を出します。psqlはこれを受け付けず、エラーで止まりました
- Geminiの道具は、SSLの設定を `"?sslmode=prefer"` という形でコマンドの末尾に付けます。psqlは警告を出してこれを無視し、そのまま接続しに行きました。警告を見落とすと、SSLの設定が効いていないことに気づけません

AIが作ったコマンドは、一度は自分で叩いて確かめます。もうひとつ、Geminiの道具は見た目を外部のサーバーから読み込んでいました。インターネットにつながらない現場では、見た目が崩れます。

## 次にやること

HTML1枚なので、思った形と違ったら捨てて頼み直せば済みます。筆者も今回、「中身はそのまま残して」の一言は、中身が消えたのを見てから足しました。失敗は、次に作るときの糧になります。

今回、筆者が確かめたのは、PostgreSQLの接続のチートシート1つと、4つのAIです。別の題材でも同じように中身が消えるのかは、試していません。ファイルを添付せずに、最初から3つ目のプロンプトを投げた場合も残るかは、まだ確かめていません。

まずは、自分が毎回書き換えているものを1つ思い浮かべて、1回目の「聞く」から始めます。聞いた答えを捨てずに残すところは、以前書いた[読んだその日に考えを残す記事]({{ site.baseurl }}/posts/save-your-thoughts-not-just-bookmarks/)と同じ考え方です。
