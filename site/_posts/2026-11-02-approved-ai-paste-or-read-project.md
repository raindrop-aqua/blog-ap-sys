現場で使ってよいAIは、会社が承認したものだけ。この記事は、そういう現場で、渡されたAIをどう使えばいいか迷っている方に向けて書きます。筆者はこの型の現場を2つ経験しましたが、同じ「承認ツールのみ」でも、渡されたAIの形によってできることがまるで違いました。

## 結論: まず、渡されたAIがどちらの形かを見分ける

承認ツールだけの現場では、ツールは選べません。渡されます。だから最初にやることは、どれが優れているかを比べることではなく、渡されたAIがどちらの形かを見分けることです。

| | 貼った分だけ型 | 読みに行く型 |
|---|---|---|
| 例 | 汎用のチャットAIを、社内向けの画面で包んだもの | GitHub Copilot、Claude Code |
| AIに見えているもの | 人が渡した部分だけ | プロジェクトの中から、AIが自分で選んで読んだもの |
| 人が決めること | どこを切り出して渡すか、前提をどう伝えるか | どのモデルで、どこまで任せるか |
| 最初の一手 | 用途ごとにチャットを分け、冒頭に環境を書く | モデル選びは後回しにして、Autoで始める |

分かれ目は、画面がチャットかどうかではありません。筆者が家で使っているClaude Codeも、話しかける画面はチャットですが、リポジトリごと渡せるので読みに行く型です。反対に、ファイルを何本か添付できるチャットでも、どれを渡すかを人が決めているうちは、貼った分だけ型です。

見分け方は、フォルダ（プロジェクト）ごと渡して、どのファイルを読むかをAIに任せられるかどうかです。

## 検証の条件: 筆者が使ってきた環境

同じ入力を投げ比べた記事ではありません。筆者が実際に使ってきた環境での所感です。

- **貼った分だけ型**: 2023年〜2025年頃。GPT-4ベースのチャットを、社内向けの画面で包んだものでした。チャット形式なので、使い心地はふつうのChatGPTとあまり変わりません
- **読みに行く型**: 2026年から使っています。この記事の内容は2026年10月時点のものです。VSCodeとGitHub Copilotです。GitHub Copilotでは、Claude・GPT・Microsoftの自社モデルから選んで使えます
- **個人の環境**: 家ではClaude（Proプラン）を使っています。GitHub Copilotは、以前に個人の無料枠でも使っていました

業務でAIが全面的に禁止されている現場と、自由に使える現場は、筆者は経験していません。この記事に書くのは、承認ツールだけの現場の話です。

## 比較結果と所感

### 貼った分だけ型: 渡した部分しか見えない

貼った分だけ型でいちばん手間だったのは、AIに渡す範囲を自分で決めて、その部分だけ切り出して貼らないといけないことでした。

裏返すと、AIは貼った部分しか見ていません。一部では正解でも、全体では正解にならないことが起こります。

たとえば、ある関数の修正を頼んで、その関数だけを貼ったときです。返ってきたコードは、プロジェクトに入っていないライブラリをいきなり使っていました。プロジェクトごと渡せていれば、AIが`build.gradle`のようなビルド設定を読んで、使えるライブラリやJavaのバージョンを自分で調べてくれます。貼った分だけ型では、それを人が毎回伝えることになります。

1回ずつは細かい話です。それでも、関数の切り出しを何度も繰り返していると、こうした細かい手間が煩わしくなってきます。複数のファイルを一度に渡して調べてもらう、プロジェクト全体を見てコーディングを手伝ってもらう、といったことは一切できませんでした。

筆者がやっていたのは、用途ごとにチャットを分けることです。Java用のチャット、SQL用のチャット、というふうに作り、最初に環境を書いておきます。しばらくはそれに従ってくれます。ところが会話が長くなると、最初に書いた環境を忘れていきます。AIが一度に覚えておける量には上限があるからです。忘れたら、また環境を渡し直す。そういう使い方でした。

### 読みに行く型: 開発の流れの中にAIがいる

今の環境のGitHub Copilotが強いのは、ソフトウェア開発の流れの中にAIが組み込まれているところです。GitHub・VSCode・GitHub Copilotがどれも同じMicrosoftのグループにあることが大きいと筆者は感じています。

筆者の環境で使っているのは、たとえば次のような機能です。

- **コミットメッセージ**: VSCodeでコミットするとき、メッセージ欄のアイコンを押すと、GitHub Copilotが変更の内容を読んでメッセージを作ってくれます
- **レビュー**: リポジトリに上げたあとも、プルリクエストのレビュアーにCopilotを指定すると、エージェントがレビューしてくれます
- **権限の設定**: エージェントにどこまでの権限を持たせるかを、VSCodeの画面から設定できます。そもそもどんな権限を付けられるのかが一覧で見えるので、仕組みを学びやすく、設定もしやすいです

前の現場で困っていた、プロジェクトに入っていないライブラリを使われる件は、今の環境では起きていません。ライブラリそのものについて質問したときも、「プロジェクトのpackage.jsonに書かれているバージョンについて調べます」のように、わざわざバージョンを断ってから答えます。

設定ファイルを見ても分からないこともあります。たとえばPostgreSQLのバージョンは、`build.gradle`を読んでも書いてありません。そういうときは、AIのほうから聞いてきます。

貼った分だけ型では、前提は人が先回りして書いて貼るものでした。書き忘れたところは、AIが推測で埋めて外します。読みに行く型では、読める前提は自分で読み、読めない前提は聞き返してきます。

### 読みに行く型で、期待と違ったこと

モデルを選べるのは便利な反面、選択肢が多すぎて、使い始めのうちは何を選べばいいか分からなくなります。

実は筆者は、自分でモデルを選ぶことはほとんどありません。普段は「Auto」にしています。Autoにすると、GitHub Copilotがその都度モデルを選んでくれて、同じモデルを直接選ぶより10%少ないクレジットで済みます（GitHubのchangelog: [VSCodeでのAutoの告知](https://github.blog/changelog/2025-09-15-auto-model-selection-for-copilot-in-vs-code-in-public-preview/)、[2026年7月の課金の更新](https://github.blog/changelog/2026-07-01-copilot-cli-auto-model-selection-routes-based-on-task)）。

ただ、Autoが選ぶモデルは毎回同じではありません。「あれ、やけにいい答えを返してくるな」と思って見ると、上位のモデルが使われていることがあります。Autoは選んだモデルの単価で課金されるので、そのときはクレジットもそのぶん多く減ります。

クレジットの減り方は、家で使っているClaudeより激しいように感じています。ただ、プランも数え方も違うので、比べ方が揃っていません。これは確かめていない肌感です。

## 使い分けの指針: 手元にあるツールでどう戦うか

### 貼った分だけ型を渡されたら

用途ごとにチャットを分けて、最初に環境を書きます。前提の書き方の例です。

```text
この会話では、Javaのコードについて相談します。前提は次のとおりです。
- Javaのバージョン: 【Javaのバージョン】
- ビルドツール: 【Gradle または Maven】
- 使えるライブラリ: 【build.gradle の dependencies に書かれているもの】
ここに書いていないライブラリは使わないでください。
```

会話が長くなって前提から外れた答えが返ってきたら、この前提を貼り直します。チャットを新しく立てて貼り直すほうが早いこともあります。

### 読みに行く型を渡されたら

モデル選びは後回しにして、Autoで始めて構いません。答えがやけに良いと感じたら、どのモデルが使われたかを見ておくと、クレジットの減り方に驚かずに済みます。

もう1つ、エージェントの権限の設定画面は、一度ひととおり眺めておくことを勧めます。どんな権限を渡せるのかが分かるだけで、AIに何をさせられるのか、何をさせてはいけないのかの地図ができます。

### 業務でAIを使えない方は

GitHub Copilotには個人向けの無料枠があり、VSCodeで拡張機能を入れれば手元で試せます。筆者もVSCodeを使っているうちに自然と入っていて、無料枠でよく使っていました。

ただ、そのころの使い方は、コードの補完を助けてもらうのがほとんどでした。今のClaudeの使い方とは全く違います。同じツールでも、補完だけで終わらせるか、プロジェクトを読ませて相談するかで、別物になります。コミットメッセージの生成やレビューが無料枠でどこまで使えるかは、筆者は確かめていません。

個人のアカウントで使う前には、入力した内容がどう扱われるかの設定を見直しておくと安心です（「[生成AIのセキュリティ設定、AI自身に確認させる]({{ site.baseurl }}/posts/check-ai-security-settings/)」）。業務でAIを使う手段がまったくない場合に、業務の外で何をしておくかは「[現場でAIが使えない間に、業務の外でやっておくこと]({{ site.baseurl }}/posts/practice-ai-dialogue-outside-work/)」に書きました。

## まとめ

明日やるなら、渡されているAIに、プロジェクトのフォルダごと渡せるかを確かめてください。渡せて、どのファイルを読むかをAIが自分で決めるなら読みに行く型、そうでなければ貼った分だけ型です。貼った分だけ型なら、用途ごとのチャットと冒頭の前提から始められます。

まだ分かっていないことが2つあります。

- クレジットの減り方が、ツールによって本当に違うのか。プランを揃えて比べたことはありません
- 全面禁止の現場と、自由に使える現場で、この見分け方がどこまで役に立つか。筆者はどちらも経験していません
