生成AIと一緒に記事を書いていて、書き上げたのに自分の記事だと思えない、という方に向けて書きます。ブログを運営する仕組みはAIと作れましたが、運用してみると、それだけでは足りませんでした。ブログの外で自分の問いを言葉にし、それをブログの仕組みに拾わせる仕組みを足した記録です。

[AIでシステムは作れるのか ― ブログの運営を仕組みにした1か月の試行錯誤]({{ site.baseurl }}/posts/ai-build-system-blog-operation/)の続きにあたります。

## 満足できた記事は、AIと話す前に言いたいことが決まっていた

このブログには、記事を書くスキルがあります。ネタ帳と設計書を読み直しながら、筆者に体験を聞き、構成を立て、下書きを作り、校閲に回します。記事は毎週出せるようになりました。

それでも、書き上げた記事の中に、自分のものだと思えないものがありました。

記事を書くスキルは、本当に記事を書くためのスキルです。新聞記者が取材してから書くように、聞いて、まとめて、整えます。けれど、書きたいことを自分の中から取り出すのは、それとは別の作業でした。筆者は2026年9月の終わりには、そこが足りないとはっきり感じていました。

13本の自分の記事を採点し直して分かったのは、満足できた回はAIと話す前に言いたいことが自分の中で決まっていた、ということでした。それを毎回の執筆の前に用意するために、足したのは2つです。

- ブログの外に、ブログを意識せずに問いを言葉にする場所
- そこから記事のタネを拾う仕組み

## 仕組みが回っても、自分の記事だと思えなかった

採点を言い出したのは、ネタ帳を審査するエージェントでした。記事の一覧表が出てきたときは、正直、面食らいました。それでも、書いた本人が自分の記事をどう感じているかを読者に伝えるのは、真摯なやり方だと思って引き受けました。

## ブログの外に、問いを言葉にする場所を作る

筆者は、ブログとは別の個人リポジトリ「Diary」に、日記や読書メモ、読んだWeb記事の要約を書いています。読んだ記事の要約については、[「あとで読む」を300件溜めた私が、読んだその日にAIと考えを残し始めた]({{ site.baseurl }}/posts/save-your-thoughts-not-just-bookmarks/)に書きました。どれもAIの聞き手と話しながら書く記録で、ブログのために書くものではありません。

2026年9月27日、このDiaryからブログの仕組みがネタを拾えるようにしました。

### 読みに行くのはブログ側だけにする

決めたことは、次の3つです。

| 決めたこと | 理由 |
|---|---|
| ブログ側がDiaryを読みに行く。Diaryからブログへは書き込まない | 日記を書くときに、ブログを意識しなくて済むようにするため |
| Diaryの記録には、ネタになりそうなものに目印を付ける | ブログ側が探すときの手がかりにするため |
| ネタ帳に積むのは、ブログ側の審査を通したものだけ | Diaryは「記録する場所」のままにしておくため |

一番大事なのは、1つ目の理由です。ブログのネタを探しながら日記を書くと、日記がブログの下書きになってしまいます。それでは、ブログの外に場所を作った意味がありません。

### 目印は、AIが提案して、自分が決める

Diaryの記録には、先頭にメタデータ（frontmatter）があります。そこに `sparks` という項目を置き、ネタになりそうなプロジェクトの名前を入れます。

```yaml
---
title: 【記事の題名】
tags: [【キーワード】, 【キーワード】]
sparks: [blog]   # このブログのネタになりそうなら blog
---
```

本文の最後には「ネタの種」という欄があり、どう使えそうかを1行で書きます。

目印を付けるのは、記録を書くときに話している聞き手のAIです。読書メモ、Web記事の要約、アイディアのメモで、それぞれ別のスキル（聞き手）がいます。どの聞き手も、会話の最後に「これはブログに使えそうですね」と一言だけ提案します。付けるかどうかを決めるのは筆者です。記録を書いている間はブログのことを考えず、最後の一言で振り分けます。

ブログ側でネタを探すスキルは、Web記事の要約と読書メモのフォルダから、frontmatter に `^sparks:.*blog` を含む記録を探します。Bashの grep ではなく、Claude Codeの検索機能で探します。理由は後で書きます。アイディアのメモは、目印は付けているものの、ブログ側のスキルがまだ探しに行っていません。

集めた候補は、ネタ帳と突き合わせます。ネタ帳には、Diaryから拾ったネタに「出典: Diary 【Diary内のパス】」と書いておきます。そこに載っている記録は、もう使ったものとして候補から外します。

日記だけは、目印を付けていません。日記にはメタデータがないので、ブログ側が直近14日分の本文を読みに行きます。

### 引き継ぎ資料は、Diary側のAIが書いた

DiaryとブログはClaude Codeで別々に作業しています。そこで、Diary側の作業の最後に、AIにブログ側宛ての引き継ぎ資料を書いてもらいました。決めたこと、Diaryのフォルダ構成、ブログ側でやってほしい変更が入った1枚です。

その日は、Diary側でAIに引き継ぎ資料を書いてもらい（14:55）、ブログ側でネタを積むスキルに「Diaryから」の入口を足してマージしました（15:44）。49分でした。

### 私的な記録を、公開する側に漏らさない

その1時間ほどあと、16:37に失敗のあと始末をしています。

ブログのリポジトリは公開しています。Diaryは私的な記録です。引き継ぎ資料には、Diaryの絶対パスと、読ませたくないフォルダの名前がそのまま書いてありました。15:36の変更で、それがブログのスキルと規則のファイルに6行入り、そのまま公開リポジトリにマージされました。

気づいたのが筆者だったかAIだったかは、覚えていません。その日のうちに、スキルと規則のファイルからDiaryの場所と非公開フォルダの名前を外し、gitで管理しない設定ファイルにだけ置く形に直しました。スキルや規則には、その設定を見に行けとだけ書いています。設定ファイルの中身は、次のような形です（場所は伏せています）。

```json
{
  "permissions": {
    "additionalDirectories": ["【Diaryの場所】"],
    "deny": [
      "Read(【Diaryの場所】/【非公開フォルダ】/**)",
      "Edit(【Diaryの場所】/**)",
      "Write(【Diaryの場所】/**)"
    ]
  }
}
```

`deny` の1行目で、非公開のフォルダを読めないようにしています。残りの2行で、ブログ側からDiaryへ書き込めないようにしています。ただし、この deny が効くのはClaude Codeの読み書きの機能に対してだけで、Bashのコマンドには効きません。そのため、スキルには「Diaryを読むときはBashの cat や grep を使わない」とも書いています。設定と指示文の両方で守る形です。

あわせて、Diaryから持ち出すときのルールをスキルに書きました。日記の文章をそのまま引用しない。人名や常駐先を特定しうる情報は、ネタ帳に書く段階で落とす。体調や家族、私生活の話はネタにしない。この記事も、そのルールの中で書いています。

## 拾えたもの、取りこぼしたもの

2026年10月25日時点で数えました。数えたのは、9月27日以降にDiaryに書いた、読書メモ・Web記事の要約・アイディアのメモです。

| | 件数 |
|---|---|
| 記録の総数 | 22 |
| そのうち `sparks` に blog を付けたもの | 18 |
| 目印を付けたもののうち、ネタ帳に拾われたもの | 13 |

目印を付けたのに拾われなかった5件のうち、2件はブログ側がまだ探しに行っていないアイディアのメモで、1件はこの記事の起点になった10月25日の記録です。この22件とは別に、目印のない記録からも2件拾われていました。日記1日分と、Diary側のスキルの定義です。日記は、目印がなくても本文を読みに行く作りなので、ここは狙いどおりです。

採点の表と合わせると、Diaryから拾ったネタで書いた記事は3本ありました。10-05、10-12、10-26 の回で、3本とも◎です。△の5本のうち4本は、前の記事の予告や延長として書いた回でした。

ただし、ここは言い切れません。10月以降の記事は、Diaryを経ていない回も含めて、すべて◎だからです。10月は、筆者が生成AIでツールを作れると分かり、その体験から記事を書けるようになった時期でもあります。自分で作って役に立つと感じたものは、自信を持って書けました。満足度が上がったのが、Diaryから拾ったからなのか、慣れたからなのかは、この13本からは切り分けられません。

共通して言えるのは、満足できた記事は、AIと話す前に言いたいことが筆者の中で決まっていた、ということです。Diaryから拾ったネタは、拾う前にすでに自分の言葉で書かれています。ツールを作った回も、作って役に立ったという手応えが先にありました。

## まとめ

次に試すのは、記事を書くスキルを始める前に、言いたいことを自分の言葉で1行書くことです。書けなければ、そのネタはまだ記事にする段階ではない、と考えます。

まだ分かっていないのは、Diaryから拾う仕組みが、慣れとは別に満足度を上げているのかどうかです。これから書く記事も同じように採点して、ネタがどこから来たかと並べていきます。

Claude Codeのような道具がなくても、同じことは手元でできます。メモアプリに日々の考えを書き、末尾に「ブログに使えそう」の1行を足すかどうかを、書き終えたときに決めるだけです。記事を書くときは、その1行で検索してから始めます。
