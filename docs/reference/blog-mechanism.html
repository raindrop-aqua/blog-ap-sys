「明日使える生成AI」ブログのひみつ

文章を書いて送ると、
自動でWebサイトになる。

このブログには、ふつうのブログサービスにある「投稿ボタン」がありません。かわりに、ファイルを1つ置いて送るだけで、ロボットがサイトを作り直して公開してくれます。そのしくみを、図でたどってみましょう。

書く→ 送る→ 自動で組み立てる→ 自動で公開される

人がやるのは前半の2つだけ。黄色い部分はロボットが担当します。

記事はどうやって、みんなの画面に届くの？

登場するのは5つ。順番にボタンを押して、いま光っているところが何をしているのか見てみよう。

書く

自分のパソコンで、記事を「テキストファイル」として書きます。WordやSNSの投稿画面は使いません。書き方のルールは Markdown（マークダウン） といいます。

送る

書いたファイルを GitHub に push（プッシュ） します。ネット上の倉庫に荷物を送るイメージです。「いつ、何を変えたか」の記録も全部残ります。

組み立てる

倉庫に荷物が届くと、GitHub Actions というロボットが目を覚まします。ロボットは Jekyll（ジキル） という機械を動かして、サイト全体を組み立て直します。人は何もしません。

公開

できあがったサイトは GitHub Pages が世界に向けて公開します。URLを開けば、だれでも読めます。

ボタンを押すと、右の図の光る場所が変わります。

## 見出しはこう書く
- 箇条書きは、行の頭に - をつける
- **太字** は星2つで囲む

ルール：ファイル名の日付が「未来」だと、その記事は公開されません。名札の date とファイル名の日付は、必ず同じにします。

Jekyll は「材料を組み立てる機械」

Webページの正体は HTML というファイルです。でも、記事ごとに手で HTML を書くのは大変。そこで、機械にまかせます。

  • 記事：自分で書いた Markdown。中身だけに集中できる。
  • デザイン：Chirpy（チャーピー）という、公開されている着せ替えセットを借りている。全部の記事が同じ見た目になるのはこのおかげ。
  • 設定：サイト名、URL、どのフォルダを材料にするか、などを書いたメモ。
  • 記事を1本足すたびに、同じ機械が同じ手順で全ページを作り直す。だから、人が手で直す場所がほとんどない。

公開されるものと、されないもの

このプロジェクトには、記事以外にも企画メモやAI向けの説明書が入っています。これがうっかりネットに出たら困りますよね。そこで、ある工夫をしています。

site/Jekyll が材料にするのは、このフォルダの中だけここだけが材料
_posts/完成した記事公開される
_drafts/書きかけの記事。本番のビルドには入らない公開されない
assets/記事の画像、デザインの微調整公開される
docs/企画メモと、書き方のルールブックサイトに出ない
infographics/ヘッダー画像を作る元データサイトに出ない
verification/記事の数字を確かめた、生のデータサイトに出ない
CLAUDE.mdAIの相棒に読ませる説明書サイトに出ない

「これは出さない」と 禁止リストを作るのではなく、「site/ の中だけを材料にする」と 許可する範囲を1つだけ決める。リストへの書き忘れが起きないので、うっかり公開の事故を仕組みで防げます。
なお「サイトのページに出ない」と「ネットで誰にも見られない」は別の話。このプロジェクトの倉庫自体は公開されているので、置いてよい中身かどうかは別に気をつけています。

記事を書くときの、ルールブックとAIの助っ人

このブログは、記事の作り方にも決まりがあります。ルールは3冊の本にまとめ、作業はAI（Claude Code）に「手順書」を渡して手伝ってもらっています。

ルールブック3冊 docs/planning/

  • content-strategy.mdブログの方針。だれに向けて、どんな分類で、どんな形の記事を書くか
  • article-backlog.md書きたい記事のストック帳。書く順番の決まりもここ
  • writing-style.md文章の口調と、体験談を書くときの守りごと

AIの助っ人

  • /add-idea思いつきや今日の出来事を、記事のネタとしてストック帳に足す
  • /write-postネタ選びから下書き、保存までを、質問しながら進める
  • post-reviewer🖍️ アカネ。書き上がった下書きを、ルールブックに照らして点検する担当
  • /add-infographic記事の一番上に載せる、図解の画像を作る
ネタを出す/add-idea→ 自分の体験を話す人がやる→ 下書き/write-post→ 点検🖍️ アカネ→ 図解/add-infographic→ push人がやる

黄色のところが、AIには代わりにできない部分です。このブログは「AIに聞けば出てくる答え」ではなく、実際にやってみた体験を載せる方針。だから助っ人は、書き手に体験をたずねて、文章の形に整える役をしています。

まわりを支える、小さな部品たち

着せ替えセット

Chirpy テーマ

見た目のもとは借り物。日本語がきれいに読めるよう、行の間隔と文字の形（BIZ UDPGothic）だけ調整しています。

読んだ人を数える係

GoatCounter

「何人が読んだか」を数える軽い道具。ページを表示するたびに1回数えます。本番のサイトでだけ動くので、手元の確認では数えません。

更新日を自動で書く係

git の履歴

記事を直して push すると、「更新日」が自動で変わります。GitHub に残っている変更の歴史を読んで決めています。

記事の顔になる画像

HTML → PNG

図解は、Webページと同じ HTML と CSS で作り、Chrome で「撮影」して画像にしています。サイズは横1600×縦840。文字は小さくしすぎないルールです。

記事の本棚は、こう並んでいる

記事には「カテゴリ」を1つだけ付けます。さらに、読む人のレベルを表す「段階タグ」も付けます。段階は、ほとんどの場合カテゴリで自動的に決まります。

入口はじめての人向け
生成AIのきほん
入口 または ステップアップ記事の中身で決める
プロンプト設計業務効率化
ステップアップ慣れてきた人向け
ツール比較Tips・小技
現場実践仕事で組み込む人向け
開発者向け
その他記事に応じて
ニュースお知らせ

カテゴリは勝手に増やしません。増やしたいときは、先に方針のファイル（content-strategy.md）を書き換えるのが決まりです。

ことばミニ辞典

Markdownマークダウン

「# を付けたら見出し」「- を付けたら箇条書き」のように、記号だけで文章の形を指定する書き方。あとで HTML に自動で変わります。

front matterフロントマター

記事ファイルの一番上にある、--- で囲んだ部分。タイトル・日付・カテゴリなどの「名札」を書きます。

HTMLエイチティーエムエル

ブラウザが読み取って、画面に表示するためのファイル。Webページの正体です。

Jekyllジキル

Markdown の記事とデザインから、HTML のページをまとめて作るソフト。GitHub Pages が対応しています。

ビルド

材料から完成品を「組み立てる」こと。このブログでは、Jekyll がサイト全体を作り直す作業のことです。

GitHubギットハブ

ファイルと、その変更の歴史を預けておくネット上の倉庫。だれが・いつ・何を変えたかが残ります。

pushプッシュ

自分のパソコンにある変更を、GitHub に送ること。このブログでは、これが「公開開始」の合図になります。

GitHub Actionsアクションズ

GitHub に何かが届いたら、決めておいた作業を自動でやってくれる仕組み。ここでは Jekyll のビルドを動かします。

GitHub Pagesページズ

GitHub がやっている、無料のサイト公開サービス。できあがったサイトを URL で見られるようにします。

コンテナ

パソコンの中に作る、小さな仮想の作業部屋。環境を汚さずに、お試し用の Jekyll を動かせます。
