# 記事ネタ帳・公開ロードマップ

「明日使える生成AI」の記事ネタのストックと、公開順序を管理する文書。方針そのものは[content-strategy.md](content-strategy.md)、文体は[writing-style.md](writing-style.md)を参照する。

- ネタが増減するたびに本書を更新する。方針レベルの変更（カテゴリの追加、ペルソナの変更など）はcontent-strategy.md側で行う
- 記事を公開したら、2章の「リンク待ちリスト」を確認して該当する橋渡しリンクを追記し、[content-strategy.md](content-strategy.md)6章のトリガーを確認する

## 2. 公開順序の依存関係

### 強い依存（この順序を守る）

先行記事が前提知識になっており、順序を逆にすると読者が置いていかれる。

| 後続 | 先に公開しておく記事 | 理由 |
|---|---|---|
| 3. プロンプト設計の型（全5回） | 2. プロンプトの基礎体力（全2回） | 型シリーズより前に読んでほしい入門編 |
| 5. ステップアップ編（全4回） | 3. プロンプト設計の型（全5回） | 型を身につけた読者向けの応用編 |
| 9. 自分のツール・エージェント（全2回） | 8. AIの拡張のしくみ（全4回） | 8はハンズオンを読むための前提知識 |
| 8-② 公式Skillsを覗いてみよう | 8-① AIの「指示の与え方」を整理する | ①で学んだ書式と照らし合わせて読む回 |
| 9-② エージェントを作ってみよう | 9-① 簡単なツールを作ってAIに使わせる | ①で作ったツールをそのまま使う回 |
| 10-① セキュリティ第2弾 | 1-① セキュリティ設定を見直そう | 「第2弾」を名乗る以上、第1弾が公開済みである必要がある |
| 10-② AIを利用した設計の方法論 | 1-⑧ コンテキストが溢れるとどうなる？ | コンテキストウィンドウの限界を前提に話を進める |

### 弱い依存（リンク待ちリスト）

記事末尾の橋渡しリンク。リンク先が未公開でも記事自体は成立するので、**リンクを省いて公開し、リンク先の公開時に追記する**。追記が済んだらチェックを入れる。

- [ ] 1-③ AIは「持っている知識」しか扱えない → 7-①（手軽な方法）／9-②（本格的な方法）
- [ ] 1-① セキュリティ設定を見直そう → 10-① セキュリティ第2弾
- [ ] 1-⑧ コンテキストが溢れるとどうなる？ → 10-② AIを利用した設計の方法論
- [ ] 1-⑨ 現場でAIが使えないときに → 7-②（相互リンク）
- [ ] 6-⓪ 業務の棚卸し → 6-①〜⑤ 業務別活用事例
- [ ] 5-④ 自分だけのエージェントとして独り立ちさせる → 9-② 本格的なエージェント構築
- [ ] 6. テンプレート活用術（2本） → 3. プロンプト設計の型シリーズ（相互リンク）
- [ ] 8-① AIの「指示の与え方」を整理する → 冒頭の交通整理から 1-③ ／ 7-① ／ 9-②
- [ ] 7-② 「社外に出せない」現場のためのAI選び → 1-① セキュリティ設定を見直そう
- [ ] 7-④ コードレビューに使えるのはどれ？ → 10-① セキュリティ第2弾

※ 1-③だけは橋渡しが記事の締めそのものなので、少なくとも7-①（手軽な方）を先に公開しておく。

### 順序を組むときの原則

- 基礎シリーズ（1. 生成AIのきほん）を連続投稿にせず、業務Tips系と交互に挟む
- `開発者向け`（8〜11）はStep1・2の記事の間に挟み込み、連続させない
- `ニュース`（12）は週1ローテーションの枠外。話題発生時に差し込む

## 4. シリーズ企画一覧

1. **生成AIのきほん**シリーズ（`生成AIのきほん`、Step1入口・全9回想定）
   1. AI利用で大事なこと①：セキュリティ設定を見直そう
   2. AI利用で大事なこと②：ハルシネーションとは何か、なぜ起こるのか
   3. AIは「持っている知識」しか扱えない ― 社内情報・ドメイン知識という壁
   4. AIに「このモデルの使い方」を聞いてみよう
   5. プランモードって何？「モード」の違いを理解する
   6. AIが扱えるファイル・形式を聞いてみよう（input / output）
   7. AIツールの便利機能、こんな時に使おう ― 検索、コードインタープリターなど各プロダクトが持つ具体的な機能と、その使いどころ。**抽象的な得意技から使い道を想像させる役割は6-⓪に持たせた**ので、ここは具体的な製品機能を「こう使う」と提示する回に徹する
   8. コンテキストが溢れるとどうなる？AIの「物忘れ」「混乱」現象
   9. **現場でAIが使えないときに、今やっておくこと** ― L0（全面禁止・未導入）の読者向け。「業務では使えない」を前提として認めたうえで、業務外で何を練習しておくか・導入されたときや提案するときに効く準備は何かを書く。価値の軸は**②立ち位置**と**③選別と順序**（一次体験より地図が効く回）
   - ※1・2は分量次第で1本にまとめるか2本に分けるか執筆時に判断
   - ※3は「学習データがいつまでか」という切り口だと検索機能付きAIには合わないため避け、**検索しても出てこない社内情報・ドメイン知識を持っていないことがハルシネーションにつながる**という切り口で書く。末尾で「その知識をAIに与えて業務に役立てるには？」として7-①（手軽）と9-②（本格）へレベル別に2本立てで橋渡しする
   - ※1はStep1向けの基本的な注意点。Step3向けの技術的な深掘り版が10-①なので末尾で橋渡しする
   - ※9と7-②は扱う範囲を分ける。**7-②は「現場の制約レベルごとに、どのツールが選べるか」**というツール選定の話、**9は「そもそも選ぶ余地がない読者が、業務の外で何をするか」**という準備の話
2. **プロンプトの基礎体力**シリーズ（`プロンプト設計`、全2回想定。型シリーズより前に読んでほしい入門編）
   1. 文章を構造化して書く基本 ― 章立て、結論ファースト・PREP法（国・教育によって「構造化された文章」を書く訓練の有無が違うという話も交えつつ、AI向けに限らず伝わる文章の基本を確認する）
   2. プロンプトの書き方の基本（Markdown記法で構造化する）
3. **プロンプト設計の型**シリーズ（`プロンプト設計`、全5回想定）
   1. 要約 ― 青空文庫など**著作権切れの小説**を使い、AIに要約・ポイント3つ抽出をさせる体験デモ（素材は著作権フリーのものに限定する）
   2. 企画書化
   3. 添削
   4. 壁打ち
   5. 役割設定
   - 追加候補: 重み付けを意識してあえて意外な出力を引き出す方法
4. **AIにキャラクターを与えてみよう**シリーズ（`プロンプト設計`、全2回想定。遊び要素が強くSNSでシェアされやすい入り口コンテンツ）
   1. AIに性格を持たせる？ペルソナ設定でAIの個性・モノマネ力を引き出す
   2. 同じ文章を「映画のヴィラン風」「元気なギャル風」「かわいいキャラクター風」に言い換えてみる（デモ中心）
5. **プロンプト設計（ステップアップ編）**（`プロンプト設計`、全4回想定）
   1. AIにプロンプトそのものを書いてもらう方法
   2. 1回のプロンプト・チャットで終わらない作業をAIにやらせる方法
   3. 複数回のやり取りで生じた矛盾を、より上位のモデルにレビュー・修正してもらう方法
   4. 書いてもらったプロンプトを「自分だけのエージェント」として独り立ちさせる ― カスタムGPT／Claude Projects／Gemini Gemsなど「保存して呼び出す」機能に落とし込む（ノーコードの話。コードを書く本格的な構築は9-②へ橋渡し）
6. **業務別活用事例**シリーズ（`業務効率化`、棚卸し1本＋全5回＋テンプレート活用術2回）
   - **⓪ 自分の業務を棚卸しして、AIに渡せる仕事を見つける**（`入口`タグ、標準型）― 「AIに何を聞けばいいかわからない」下限読者の入口。**業務の棚卸し → AIに渡せる／渡せないの判定軸 → 実際に渡してみる最小の一歩**まで手を動かす構成にする。きほん型（困りごとから入る）は使わない（まだ困った経験がないため）。一次体験は**筆者が自分の業務を棚卸ししたときの実物リスト**で、渡せると思って外れたものも必ず載せる
   1. 議事録
   2. メール
   3. 資料作成
   4. データ集計
   5. 企画立案
   - **テンプレート活用術**（2部構成。`プロンプト設計`の型シリーズと相互リンク）
     1. 業務別テンプレート集 ― 議事録・メール・提案書などの叩き台テンプレートを配布
     2. 「上手なテンプレートとは何か」を考える回 ― テンプレートは項目を埋めようとするほど冗長になりがち、という課題から出発する。たたき台仮説（**執筆時に検証して確定させる**）: 項目名を名詞ではなく疑問文にする／「使わない項目は消してよい」と明記する／項目ごとに分量の目安を指定する／「AIへの指示テンプレート」と「成果物のテンプレート」を分ける
7. **ツール使い分け**シリーズ（`ツール比較`、全6回想定）
   1. ノートブック機能で「自分だけのナレッジ」を作る ― マニュアルや資料をまとめて投入し、簡易的なRAGとしてチャットで質問できるようにする（厳密には自前でRAGを構築するわけではなく、ツールが検索して回答に活用する仕組みを代行してくれるイメージ、という補足を入れる）
   2. **「社外に出せない」現場のためのAI選び** ― 制約レベル（全面禁止／社内承認ツールのみ／個人利用は黙認／自由）ごとに何が選べるかを整理する。ツールを横並びにせず**制約の型を軸にツールを当てはめる**構成。このブログでしか書けない切り口なのでシリーズの入口に置く。「業務外で何を練習するか」は1-⑨に譲る
   3. **長文要約はどれが強い？** ― 要約の巧拙だけでなく、**投入できる長さの上限**と**貼り付けかファイル添付か**という運用面の差を必ず見る。素材は著作権切れの文書か自作ダミー
   4. **コードレビューに使えるのはどれ？** ― 欠陥の種類を分けて仕込む（null安全・境界値・性能・命名）。検出数だけでなく**指摘の粒度**と**存在しない問題を指摘してこないか**を見る。末尾は「常駐先のソースを貼れない現場でどう使うか」に着地
   5. **Excel・表データの処理はどれが得意？** ― 回答の賢さより、ファイルを直接扱えるか・コード実行環境を持つか・xlsxで返せるかという**入出力の差**が本命。添付禁止の現場向けにテキスト貼り付けの手順も併記
   6. **無料プランだけでどこまで戦えるか** ― 各無料枠で同じ1日の業務を回し、どこで最初に止まるか（回数制限・使えるモデル・添付可否）を見る。**プラン内容の変化が速く陳腐化しやすい**ので検証時点を強調し、更新前提で扱う
   - ※全記事が比較型フォーマット。検証条件・検証時点の明記は[content-strategy.md](content-strategy.md)5章に従う
   - ※比較対象のツール名は書いてよいが、**どのツールが常駐先で承認されていたかは書かない**（[writing-style.md](writing-style.md)4章）

開発者向け（Step3）は項目数が多いためテーマ別に4つのサブシリーズへ分割する。他シリーズの間に挟み込む点は変わらない。

8. **AIの拡張のしくみ**シリーズ（`開発者向け`、概念編・全4回想定）
    1. AIの「指示の与え方」を整理する ― Instructions / Skills / Agentsの基礎概念、各AIでの指定方法・呼び方の違い、実際の書式（SKILL.mdのフロントマター＋Markdown本文など）。**冒頭で「AIに何かを足す」2系統の交通整理を入れる**: **知識を足す**（1-③・7-①・9-②で扱う）と**機能・ツールを足す**（本シリーズ本題）。この地図があると、他シリーズで散発的に出てくる話を読者が位置づけられる
    2. Anthropic公式のSkills(https://github.com/anthropics/skills)を覗いてみよう ― 公開されているSkillsを①の書式と照らし合わせて読む
    3. MCP（Model Context Protocol）とは何か ― AIとツール・データソースをつなぐ標準規格
    4. MCPを使うときの注意点 ― 有効化したMCPサーバー・ツールの一覧は常にAIへ渡されるため、使わなくてもトークンを消費する。必要な時だけONにする運用
9. **自分のツール・エージェントを作ってみよう**シリーズ（`開発者向け`、ハンズオン編・全2回想定。8を前提知識として読んだ後の実践編）
    1. 簡単なツールを作ってAIに使わせる（例: 天気予報取得ツール）
    2. 簡単なエージェントを作ってみよう（①のツール＋AIで「今日のお出かけプラン」を提案させる）
10. **開発者としてのAI活用ノウハウ**シリーズ（`開発者向け`、実践編・全4回想定）
    1. セキュリティ第2弾：AIに与えてはいけない情報（認証情報・DB接続情報など）― AIが自発的にDBへ接続・システムへログインしてしまうリスクを扱う
    2. AIを利用した設計の方法論 ― コンテキストウィンドウの限界を踏まえ、仕様を適切な粒度に分解し互いに影響しないよう設計する（結果として人間にも理解しやすい設計になる、という繋ぎ方）
    3. AIが得意な開発言語はどれ？ ― 学習リソース量／AIはコードの意味を理解していないという前提から、型付き言語の有利さと実行環境整備の重要性を考える
    4. 確率論と決定論の使い分け
11. **現場導入・推進**シリーズ（`開発者向け`、マネジメント編・全2回想定）
    1. 現場の生成AI導入レベルを診断してみよう
    2. 現場に生成AIを導入してもらうときのアピール方法
12. **ニュース**枠（事前にネタを積まず話題発生時に随時執筆。3類型は[content-strategy.md](content-strategy.md)3章）
