# 記事ネタ帳・公開ロードマップ

「明日使える生成AI」の記事ネタのストックと、公開順序を管理する文書。方針そのものは[content-strategy.md](content-strategy.md)、文体は[writing-style.md](writing-style.md)を参照する。

- ネタが増減するたびに本書を更新する。方針レベルの変更（カテゴリの追加、ペルソナの変更など）はcontent-strategy.md側で行う
- 記事を公開したら、2章の「リンク待ちリスト」を確認して該当する橋渡しリンクを追記し、[content-strategy.md](content-strategy.md)6章のトリガーを確認する

## 0. 記事番号（ID）の付け方

記事は、題名でも公開順でもなく、IDで呼ぶ。題名は執筆中に変わり、公開順は割り込みのたびにずれるが、IDは一度付けたら変わらない。

### 形

`📝<カテゴリの英字2文字><シリーズ番号>-<回の番号>`。回の番号は2桁、シリーズ番号は桁をそろえない。例: `📝KH1-02`（生成AIのきほん・シリーズ1・2回目）、`📝GK6-00`、`📝DV10-05`。

- 文書の中では必ず 📝 を付ける。記事を指していることが一目で分かるようにするため
- front matter、フォルダ名、grep のときは 📝 を外して `KH1-02` と書く（絵文字はファイル名やYAMLで扱いにくい）
- 範囲や並びは `📝DV13-01〜DV13-04`、`📝GK6-06・GK6-07` のように書いてよい

### カテゴリの英字

| カテゴリ | 英字 |
|---|---|
| `生成AIのきほん` | `KH` |
| `プロンプト設計` | `PR` |
| `業務効率化` | `GK` |
| `ツール比較` | `TL` |
| `Tips・小技` | `TP` |
| `ニュース` | `NW` |

| `お知らせ` | IDを付けない |

カテゴリを増やすときは、[content-strategy.md](content-strategy.md)3章を先に直し、この表に英字を足す。

### 付けるとき

| 記事の種類 | いつ付けるか | 形 |
|---|---|---|
| シリーズの回・追加候補 | ネタ帳に積んだとき。そのシリーズで次に空いている回の番号を使う | `📝PR3-06` |
| `ニュース` | 公開したとき（事前に積まないため）。4章のシリーズ12に1行足す | `📝NW12-NN` |
| `Tips・小技` | 公開したとき（事前に積まないため）。4章末尾の「TP」に1行足す | `📝TP-NN`（シリーズ番号なし） |
| `お知らせ` | 付けない | ― |

### 変えないこと・使い回さないこと

- 題名が変わっても、公開順が動いても、IDは変えない
- ボツにしたネタや、既存ネタに統合したネタのIDは使い回さない。4章の該当行を消さずに「欠番（〇〇へ統合）」と書いて残す
- 「切り出すなら新しい番号で」のように、まだ積んでいないネタに番号を取り置かない

### カテゴリ・シリーズが変わったとき

IDにはカテゴリとシリーズが入っているので、別のシリーズへ移したら新しいIDを振る（同じカテゴリの別シリーズへ移すときも同じ）。古いIDの行は「欠番 → 📝GK6-08 へ移動（日付）」と書いて残す。この文書の中で古いIDを使っている箇所はすべて新しいIDに直し、記事の front matter の `backlog_id` も直す。

### 呼び方

- 記事はIDで呼ぶ。3章の表の「#」は行番号なので、記事を指すのに使わない
- 「〇章」はこの文書の章にだけ使う。4章のシリーズは「シリーズ5」と書く

### 記事ファイル・検証データとの対応

- 記事の front matter に `backlog_id: "PR2-03"` を書く（`/write-post` の保存時）。表示には使われない
- 2026-09-25より前に公開した記事にはまだ無い。front matter だけを直すと、更新日の仕組み（`site/_plugins/posts-lastmod-hook.rb`）で「更新」と表示されてしまうため、次にその記事の本文を直すときに一緒に足す
- `verification/` の保管フォルダは、公開前は `_pending-<ID>-<英語スラッグ>`（例: `_pending-GK6-00-inventory-your-work-for-ai`）、公開後は投稿ファイル名（CLAUDE.md の Verification data）。シリーズ全体で共有するものは `_pending-<IDの頭>-<英語スラッグ>`（例: `_pending-DV13-perf-investigation-agent`）
